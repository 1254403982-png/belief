# 跨设备同步接入计划

当前版本仍是本地账号和 IndexedDB 数据。网站部署到 Vercel 本身不会同步用户数据。本轮没有创建云端资源、上传个人记录或修改线上部署。

## 面向中国大陆用户的推荐落地方案

- 长期对外开放：网站和后端统一迁到腾讯云 CloudBase 中国大陆环境。它提供 React/Vite 静态托管、身份认证、数据库与云函数；使用自有域名并完成相应 ICP 备案。GitHub 仓库仍可作为代码源。
- 较快试用：可先选择香港等境外机房以省去大陆服务器的 ICP 备案流程，但跨境访问质量需从中国大陆不同网络实际测试，不把它当作稳定性保证。
- Vercel + Supabase 是保留海外部署的可选方案；若国内稳定直连是主要目标，不将它作为默认方案。无论采用哪种托管，单纯搬迁前端都不会让本地账号跨设备同步。
- 云端登录推荐邮箱验证；所有数据按云端已验证的用户 ID 隔离，CloudBase 文档型数据库配置仅本人可读写的安全规则。旧本地密码哈希不上传作为云端认证。
- DeepSeek 请求改走经云端登录校验的云函数。`DEEPSEEK_API_KEY` 仅保存在服务端，不再使用 `VITE_DEEPSEEK_API_KEY`；上线后轮换曾用于前端构建的旧密钥。

**迁站时的数据边界**：IndexedDB 按网站来源隔离，新域名不能直接读取旧 `belief-five.vercel.app` 的本地记录。切换前在每台旧设备导出 JSON；新站提供经确认的导入/迁移流程，逐个绑定到云端账号，核对节点、连线、探索、待办和书籍问答数量后再停止旧站。不能按相同用户名自动合并，也不能把“上传完成”当作“已同步”，应等待服务端确认。

云环境并非永久保险箱。网站代码重新部署通常不删除独立数据库，但误删环境、欠费停服后释放或未备份的误操作仍可能导致数据丢失。保留本地缓存和可下载 JSON，配置云端自动备份、续费/用量告警与定期恢复演练。

参考：[CloudBase 产品能力](https://cloud.tencent.com/document/product/876/18431)、[静态托管与 Git 部署](https://cloud.tencent.com/document/product/876/46900)、[CloudBase 备案条件](https://cloud.tencent.com/document/product/876/128405)、[数据库安全规则](https://cloud.tencent.com/document/product/876/41802)、[数据库回档](https://docs.cloudbase.net/database/backup)、[Vite 环境变量](https://vite.dev/guide/env-and-mode)。

## 已明确的数据边界

- `conversationSessions` 是探索记录的主数据：原话、问题、未提交草稿、历次整理、用户改写分别保留。
- `bookChats` 按账号和书籍保存问答记录；未来同步时同样需要按消息 ID 去重，且保留每轮是否结合个人信念的模式。
- `beliefNodes.sourceSessionId/sourceSummaryId/sourceCandidateId` 指向用户主动保留内容的来源。入图不自动代表因果关系或生成连线。
- `dailyTasks` 只记录行动完成状态，整理思考不改变任务完成状态。
- `src/db/explorations.ts` 集中处理探索保存与入图事务，后续可接入同步写入队列；其他旧功能仍直接访问 Dexie，需要逐项迁移。

## 云端落地前需要的配置

1. 选定托管区域和账号/数据库服务；大陆正式环境先准备域名与备案，决定用户使用邮箱还是其他方式登录。
2. 建立统一云端身份。所有查询和写入在服务端按已验证的登录身份隔离，不能信任客户端传入的 `userId`，也不能按相同用户名自动合并本地账号。
3. 将模型凭据和请求鉴权移至服务端。当前 AI 调用仍读取 `VITE_DEEPSEEK_API_KEY`，此值会进入客户端构建，不能作为正式云端鉴权方案。所有已登录用户免费使用 AI；迁移后轮换已公开发布过的凭据。

## 同步与迁移顺序

1. 完成云端注册、登录和退出；将旧密码验证留在本地迁移流程中，不上传旧密码哈希充当云端认证。
2. 用户登录云端账号后，展示当前浏览器待迁移的数据范围，再确认归属。先保留完整本地备份。
3. 按批次幂等迁移，维护旧 ID 与新 ID 的映射；同步节点、连线及探索来源引用，迁移失败不清空本地记录。
4. Dexie 保留本地缓存与待同步队列，展示“已保存本机 / 待同步 / 已同步 / 需要处理冲突”。服务端成功确认后才显示已同步。
5. 服务端使用版本号处理并发修改。同一段草稿被两台设备修改时保留双方版本；探索消息按稳定消息 ID 追加和去重，不能用整段覆盖。
6. 删除保留可同步的删除标记，避免离线设备把已删内容重新带回。删除与来源引用保留策略需明确。

## 验收场景

- 设备 A 写下两轮思考与草稿，设备 B 登录后看到完整内容并继续。
- A 离线写作、B 在线修改，A 恢复网络后两份内容都能找回。
- 账号 A 不能读取、修改或通过伪造 ID 访问账号 B 的任何记录。
- 迁移重复执行不产生重复节点；连线、旧会话、来源引用保持正确。
- AI 密钥不出现在浏览器构建中；无有效登录时服务端拒绝相应 AI 请求，手动记录仍可用。
